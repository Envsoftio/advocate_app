# Synthetic PDF admission corpus

Run `backend/.venv312/bin/python samples/rust_pdf_corpus/generate.py` to regenerate. Then run `backend/.venv312/bin/python samples/rust_pdf_corpus/verify.py` to check the files without changing them. The generator overwrites only files in this directory and writes `manifest.json`. Run it twice and compare SHA-256 values to check reproducibility. `synthetic_key.pem` is deliberately public test material; its certificate establishes no trusted identity.

The base one-page PDF is made by PyMuPDF. `generate.py` writes proper incremental xref/trailer sections for the signed files, reserves a `/Contents` gap, computes `/ByteRange`, signs the covered bytes with a detached PKCS#7 CMS signature and fills the gap. It also creates a two-revision signed file, escaped `/Byte#52ange`, catalog `/Perms`, object-stream input, unsigned AcroForm/Perms, a visible text mark without a certificate signature, and a truncated malformed file. The object-stream files use PyMuPDF `use_objstms=1`. The AES-256 PDF was generated with PyMuPDF using synthetic owner/user passwords and is pinned in `encrypted_seed.b64`: PyMuPDF encryption uses fresh randomness, so regenerating encryption directly would change its SHA-256 on every run. The seed is public test data, not a secret.

`manifest.json` records SHA-256, byte length, PyMuPDF open/page/encryption/signature-field results, and OpenSSL `cms -verify -noverify` results for signed files. The separate `verify.py` checks manifest hashes, traverses parsed PDF objects to locate `/ByteRange`, checks the exact covered-byte gap and DER length, then asks OpenSSL to verify the detached CMS. This is independent of the generator's regex extraction. OpenSSL success checks the CMS cryptographic digest against the declared byte ranges; `-noverify` intentionally does not establish certificate trust. PyMuPDF `get_sigflags=-1` means no signature fields were found, **not** legal or cryptographic proof of an unsigned document. The visible mark is just text. A third PDF validator, adversarial structural review, target packaging and memory/durability evidence are still required before any broader admission.

The Rust test `independently_checked_pdf_corpus_stays_outside_pinned_admission` proves that every corpus file is refused by the current exact-byte gate without creating a document folder. None of these files is an admitted production class.
