## Implementation and existing contracts

The design scope is ED31, ED32, ED30, ED26, ED33, 11C and 14C. Read the repository handoffs and scoped JSON, resolved 19 reusable components and 340 descendant overrides, and checked the shared semantic values in both themes. Viewed supplied ED31, 11C and 14C previews. No Pencil MCP, `.pen` access, master JSON dump, new UI library or cloud dependency.

- **Artifact context:** the existing working reader exposes a version selector using the actual document revision and retained build/file identities. Original and generated review reuse the authenticated PDF.js reader, controls and lifecycle in `ExportPdfReview.vue`. Original PDFs reuse the virtual thumbnail rail in a read-only mode. Working reader/search/panels remain mounted while the artifact dialog is open. Original, working and export positions use separate keys in the existing protected reader-position store. No database migration.
- **Original permissions:** authenticated GET/HEAD routes serve the retained original after checking its import hash. They expose no filesystem path and have no mutation methods. PDF original counts come from those original bytes, independently of the working copy. PNG/JPEG originals display their image bytes, explicitly distinguished from converted working PDFs. Password-protected originals report unavailable preview; decrypted working bytes are never labelled as the original. Generated review retains immutable export identity, range access and the existing stale-build warning. Mutation services still exclusively target working paths.
- **Navigation:** the existing guard now offers a real Save in addition to Discard and Keep editing/Cancel. It retains the suspended call's destination and origin until the choice resolves. Metadata, settings, output policy and supported PDF-tool drafts call their existing persistence operations. Incomplete or failed PDF commits keep the dialog and draft; failed metadata/settings saves block navigation. Cancel restores invoker focus; keyboard focus stays within the guard. Existing per-tab metadata/settings drafts remain retained on ordinary tab switches. Inactive dirty tabs must be activated to save their drafts before closing a group; the guard explains this rather than pretending to save them.
- **Revision and async safeguards:** existing locked candidate-copy page operations, revision checks, SQLite revision history and staged/atomic build publication were inspected and retained. OCR now captures the submitted revision and rejects a different revision when the queued task starts; the UI sends an explicit expected revision. Queued builds capture the existing complete build-input digest and reject changed inputs. Frontend matter/validation/link/settings loads reject superseded responses; output-policy responses do not overwrite newer drafts. Tab activation waits for the authoritative resource load before restoring its draft.
- **Derived state:** Preflight findings and page-preview responses carry the existing build-input fingerprint. Preview responses also record their requested volume settings. Draft or processing changes hide current map rows and say pending; loading/failure clears incompatible rows instead of retaining a successful-looking old map. Validation loading/failure is explicit, with last-saved-snapshot wording for pending local inputs. Retained generated bytes, manifests and recorded page maps stay frozen. No volume/index/numbering calculation changed; all remain in `backend/app/engine.py`.
- **Exact Preflight context:** real page findings carry document ID, working revision, zero-based source position and deterministic finding ID. The reader verifies the requested revision/range and refuses stale targets rather than clamping a finding onto another page. Document-wide findings do not acquire fabricated page targets. The entry preserves its originating tab and finding, provides Return to Preflight and restores focus after the workspace transition. Original-integrity findings identify the original artifact.

## Identity adapter and boundaries

The observed model already has immutable document/build IDs and revision-qualified positional anchors. This task uses `(document ID, working revision, source page index)` as an exact anchor, **not** as a stable page identity across edits. A reorder or revision change invalidates an old finding; it does not silently remap it. Printed volume numbers and combined PDF positions remain outputs of the deterministic engine map, separate from source positions. No page-lineage schema, migration, selected-page bundle variant, comparison or later editor mode was introduced. Historical working revisions are not exposed as an arbitrary revision browser.

ED30 contributes failed-save/context-retention requirements here. Broader compact/dark/offline adaptation remains 02C; no offline cache or successful processing fallback is invented. The existing Phase 01 Details/overflow behavior and Phase 02A reading workspace must pass unchanged geometry assertions.
