# Rust matter resources and synthetic PDF import contract — 18 November 2026

This is a bounded development contract for `MATTERDRAFT_BACKEND=rust`. Python remains the default and owns the full document workflow. Rust's app-local `rust-synthetic-v1` store upgrades schema 1 to schema 2 in place; it never opens the Python database or vault. `workflow_ready=false` remains.

## Requests made around a matter

| UI request | Python reference | Rust pilot |
| --- | --- | --- |
| `GET /matters`, `/matters/archived`, `/matters/{id}` | Active/archived lists and active detail; missing or archived detail 404 | Metadata parity, including timestamps and archive state |
| `GET /matters/{id}/documents` | Active documents ordered by `position,created_at` | Real Rust documents ordered by `position,created_at,id`; reads verify original and revision hashes, returning 409 for missing/changed files; missing/archived matter 404 |
| `GET /matters/{id}/archived-documents` | Archived documents, newest archive first | Real Rust table read; empty because document archive is unsupported; missing/archived matter 404 |
| `GET /matters/{id}/storage` | Filesystem totals for originals, working, exports and other | Real original and revision byte totals; missing/changed file 409; exports/other zero because Rust creates neither |
| `GET /matters/{id}/audit` | Newest 500 events with action, document ID and timestamp | Newest 500 Rust events with same keys; import writes `document_imported` |
| `GET /matters/{id}/history` | Full matter/document edit history and replay | Metadata replay plus import's `document_presence` entry; Undo is disabled when that unsupported entry is next. Direct replay request returns 409 without mutation. |
| `GET /matters/{id}/exports` | Completed build manifests | `[]` for Rust-owned matters because Rust cannot build or export; missing/archived matter 404. Used by the Matters count summary. |

| `GET /matters/{id}/validate`, `/jobs`, `/bookmarks`; preview, thumbnail, original and revision PDF paths | Full Python workflows | 501 or explicit UI guard. No zero checks, fake previews, or Python delegation. |
| `POST /matters/{id}/documents/raw` | PDF/PNG/JPEG up to 80 MB with optional protected-PDF handling | Direct `rust_import_pdf` IPC accepts only bytes with the SHA-256 of `samples/01_petition.pdf` on Unix. Other PDFs return 422 before parsing, and Windows import returns 501 pending durability qualification. No Python route/HTTP server. 404 inactive matter, 415 other extension, 413 over 4 MiB at the transport gate, 422 invalid/path-like/nonfixture input, 409 duplicate source hash. |

The home view asks for documents and exports for each active matter; Overview and Documents consume the same document list. Import staging reads that list to reject duplicates before dispatch, and the Rust core repeats the check under the SQLite writer. Python and Rust return the same empty resource shapes and 404s in the 412-case live fixture, plus a synthetic PDF import subset comparing SHA-256, page count, filename, position, revision and reference-only membership. Rust intentionally has a smaller upload limit, no source file mtime, no preview endpoint, no image import and no document replay.

## Ownership and failure boundary

The fixed Rust path is `<app_local_data_dir>/rust-synthetic-v1/documents-v1/<32-hex-document-id>/`. The original is `original.pdf`, read-only after import, and the separate first working copy is `revision-1.pdf`. SQLite schema 2 records the source hash, fixed relative paths, document metadata and revision 1. The caller supplies bytes and a plain filename, never a destination path. The original is not the caller's source file; the caller's file is read and not modified.

**Qualification restriction, 18 November 2026:** [Certain] General PDF admission is disabled. Only the exact 6,004-byte repository fixture `samples/01_petition.pdf`, SHA-256 `76da5e34c1799a5aff3d3e9bec8cc689cb6cf8430dfc163f93bfc3ec286bf17a`, reaches PDF Oxide on Unix. A SHA mismatch returns 422 before parser construction, byte-array IPC conversion in the normal UI, or any store write. The queue marks changed files excluded, not ready. The direct core/Tauri command also enforces this hash. Windows returns 501 because directory sync/rename durability is not implemented there. The filename may differ, but the bytes must match. This is a byte allowlist, **not** a certificate-signature detector. The fixture's simple 34-object xref/trailer was inspected, its catalog has no AcroForm/Perms, and its raw bytes have no ByteRange, Sig, Encrypt or object-stream marker; no signer identity or legal validity is inferred. Its stored certificate status remains `unknown`.

[Certain] Changed copies with ordinary/escaped ByteRange, AcroForm/Perms, incremental-update-like, object-stream-like, Encrypt, visible-mark-like and malformed suffixes are refused by their different hash. These suffix cases test the admission boundary; they are not a validated corpus of independently signed PDF documents. The PDF Oxide signature feature still could not compile offline because `cms` was uncached and crates.io DNS failed. General import requires independently validated ordinary and incremental signatures, escaped names and object-stream fixtures, encrypted and visible-mark-only controls, and a maintained detector or independently checked structural inspector that rejects ambiguity.

The core begins a SQLite immediate transaction before staging. It writes both files in a unique `.staging` directory, syncs the files, makes the original read-only, renames the directory to its fixed document ID, syncs the parent on Unix, verifies both SHA-256 readbacks, then commits document, revision, history, audit and matter timestamp together. A second process cannot run startup orphan cleanup while the first holds this writer transaction. On normal failure, uncommitted staging/published files are removed; an uncertain SQLite commit leaves files in place if metadata exists. Reopen removes orphan staging and unpublished document directories. A committed document with a missing or changed file is refused with 409. Resource reads cross-check the document body, SQL source hash, fixed paths, revision row and each file's recorded hash; stale revision metadata returns 409. [Certain] Child-process exit at staging, first/second sync, rename, precommit publication and postcommit was tested: reopen found zero uncommitted records/folders or one committed record with both exact bytes. A second process waited through an active writer's staging period. SQLite-trigger failure and rename collision kept the caller source and unrelated files intact. These tests do **not** simulate power loss, disk full, external same-user tampering or Windows semantics. Directory fsync is not implemented on Windows, so Windows import is refused. The 4 MiB `File.size` gate runs before IPC; the normal UI checks the pinned hash before converting to a JSON byte array. Tauri deserialization and Rust copies still lack a hard memory cap. The near-limit 4 MiB and over-limit 4 MiB+1 core cases were refused; the isolated near-limit core test process used 19,120,128 bytes peak RSS on this Mac, which is measurement, not a bound.

No document archive/restore, page editing, OCR, preview, PDF writer, build, export, portable backup, vault migration, durable import job, cancellation of a started import, or planner replacement is implemented. A caller timeout is not cancellation and must not trigger automatic retry; refresh the matter and check its document list before deciding whether to import again. The deterministic page map remains in `backend/app/engine.py`.

Next gate: retain the byte allowlist until validated signed/encrypted/visible-mark fixtures and an ambiguity-refusing detector, parser memory limits or scoped transport, power-loss/disk-full recovery, Windows directory durability and target-device evidence support broader admission. `document_presence` remains visible but non-replayable; direct Undo/Redo of that entry returns 409 without mutation. Python remains default and `workflow_ready=false`.

## Restricted-pilot gap closure — 18 November 2026

[Certain] The byte allowlist is now enforced by exact length (6,004 bytes), SHA-256 and byte equality in the core before PDF Oxide. The normal UI and transport refuse wrong-sized files before `File.arrayBuffer()`; direct IPC still deserializes its byte array before the Rust command can check length, so this is **not** a hard hostile-IPC memory cap. The 4 MiB transport ceiling remains a defensive upper bound, not an accepted PDF size.

[Certain] Import rechecks active-matter status inside the same immediate writer transaction that publishes the document. A child-process fixture pauses after the first status check, archives the matter through a second store, then verifies import returns 404 with no file or document row. Startup now removes only interrupted staging folders containing empty or prefix copies of the pinned fixture, and unpublished folders containing both complete pinned files. A UUID-shaped folder containing foreign content, or an empty unpublished folder, is preserved and store opening fails closed. This avoids deleting unrelated collision files. Incomplete older or tampered folders may require manual inspection; they are never silently deleted.

[Certain] Resource reads now compare body ID, matter ID, archive state, page count, signature status and source hash with the selected SQL row and the pinned fixture. Revision 1's recorded hash must equal the source hash, and both files must match their own recorded hashes. Stale body/SQL values return 409 instead of presenting another document's bytes or a false signature claim. Five injected file failures before sync, directory sync and readback roll back with no orphan, record, audit or history publication. The previous six process-exit fixtures remain passing. None of this proves power-loss durability, Windows directory sync or full signature detection.

General-admission checkpoint: [Certain] The [12-file synthetic corpus](../samples/rust_pdf_corpus/README.md) includes five independently CMS-checked certificate-signature variants, encryption, malformed and unsigned controls. All return 422 under the Unix exact-byte gate without creating a document; Windows remains 501. These results prove refusal by identity, not reliable signature classification. `certificate_signature_status=unknown` remains the only persisted status for the pinned import. `pdf_oxide/signatures` cannot build offline (`cms` missing); direct IPC JSON allocation, disk-full/power-loss and Windows flush/rename remain open. No route or resource response is broadened.

Tauri argument follow-up: `rust_import_pdf` now deserializes into a capped 4 MiB sequence rather than an unbounded `Vec<u8>`; extraction and job-start arguments are capped at 16 MiB. The normal UI's size/hash checks and the core's exact-byte gate remain. This limits the constructed Rust byte vector, but the Tauri host may have buffered raw JSON first; total IPC memory remains unqualified. Direct oversize argument rejection occurs during command deserialization, while the normal UI preserves explicit 413/422 responses. See [acceptance](ACCEPTANCE_TESTS.md#bounded-tauri-pdf-argument-and-next-lifecycle-mapping--18-november-2026).

## Native token import and document lifecycle — 18 November 2026

This section supersedes the older byte-array IPC and non-replayable `document_presence` descriptions above. [Certain] The exposed Tauri commands `rust_import_pdf`, `rust_extract_text` and `rust_job_start` that accepted PDF byte arrays were removed. In the Rust pilot, the native picker opens a local file and returns only an opaque token, name, byte count and SHA-256. The picker refuses Windows with 501; on Unix it requires a regular file, exact 6,004-byte length and pinned SHA before staging a handle. `rust_import_picked_pdf` consumes the token, reads at most 6,005 bytes from the same open handle, rechecks the hash and sends the exact bytes to the UI-independent core on the bounded SQLite worker lane. The picker retains at most eight handles; discard releases a token, and reuse fails. The normal HTML File path returns 501 before `arrayBuffer()` in Rust mode. This removes the PDF byte-array path from the exposed Tauri IPC surface, including the raw-JSON-before-Serde gap for **this pinned import path**. It does not put a global bound on arbitrary Tauri JSON, PDF Oxide allocation, or future general PDF import. The core still enforces exact-byte admission; all other PDFs remain refused and `workflow_ready=false`.

The Python route shapes, history labels, order and 100-entry retention were checked against `backend/app/main.py`, `storage.py` and live synthetic Python/Rust requests. Normalization in the paired fixture covers generated IDs/timestamps only. In Rust, each real archive/restore and replay runs in one SQLite immediate writer transaction covering document body/archive state, history applied flag or branch insertion, audit and matter timestamp. Real new edits clear the redo branch and keep the newest 100 entries. Archive/restore audit actions are `document_archived`/`document_restored`; replay actions are `edit_undone`/`edit_redone`. Failed or repeated calls publish none of these. The Rust restore hash requirement is a reviewed safety deviation from Python's current restore, not a claim of identical failure behavior under corrupted files. Caller timeout is not cancellation and must not trigger an automatic mutation retry.
