# Local security and retention state

**Status:** DAT-07 engineering implementation, 15 October 2026. Use synthetic matters until native macOS and Windows acceptance checks are complete. Hashes, OCR, audit records and an export do not establish legal authenticity.

## Protected boundary

Packaged Tauri launches the loopback Python sidecar with a random bearer token and requires vault setup or unlock before matter routes work. Browser development mode remains a plaintext test mode with a fixed development token. The vault uses a random 256-bit data key, wrapped separately by a user password and a one-time recovery key using scrypt and AES-256-GCM. The recovery key appears once; the app does not persist its plaintext. Changing the password creates a new recovery key and revokes both old credential slots. Losing both current credentials makes the encrypted data unrecoverable.

The minimum vault password length is six characters. Short passwords are easier to guess; users should choose a longer password when possible and store the one-time recovery key separately.

SQLCipher encrypts the SQLite database, including its WAL. Originals, historical and current working revisions, generated exports, build staging, quarantine, upload and portable-transfer scratch are stored as authenticated, chunk-encrypted files under the data root. Protected document imports and backup restores accept streamed binary requests and write directly into encrypted scratch, including when an oversized request is rejected. The legacy multipart endpoints remain available only in plaintext development mode. PDF operations decrypt into process memory. A protected `.cbmatter` backup contains an encrypted ZIP and a versioned key envelope so it can be restored on another vault with the source password or recovery key. Imported original bytes are preserved inside their encrypted container and verified by hash after decryption. Explicit PDF/ZIP downloads and files saved through the native picker are plaintext at the destination chosen by the user.

The data root is tightened to `0700` on POSIX. Metadata and encrypted file candidates use owner-only permissions there. Startup removes interrupted package and PDF-edit candidates; uncommitted revisions are quarantined. A versioned legacy migration encrypts matter files and then migrates SQLite under the engine's exclusive lock. An interrupted migration resumes on unlock. Until it finishes, legacy plaintext may still exist in that root. Make a separate, verified backup of a legacy store before migration; moving to the vault does not retroactively encrypt external copies, OS snapshots or earlier plaintext `.cbmatter` backups.

This boundary does not protect against a local administrator, malware or another process with access to the unlocked user's memory, screen or session token. Files may also be exposed through OS swap, crash dumps or user-selected plaintext exports. Protected backup creation now encrypts ZIP output as it is written, but backup restore and export ZIP creation still buffer data in memory; large matters can exhaust available RAM despite the backup format's 4 GiB limit. Release sizing and remaining streaming work are open. Windows ACL and native save behavior need target-device verification. No confidential client matter should be imported based on synthetic tests alone.

## Retention, audit and logs

Matter and document removal archives SQLite records and retains originals, revisions, exports and reusable values. There is no in-app permanent delete. Portable backups include active and archived documents, originals, revisions and matter metadata, but not generated exports or job history. Restore assigns new matter and document IDs and validates paths, sizes and hashes. A hash is an integrity comparison, not proof of authorship.

SQLite audit events contain action codes, matter/document IDs and UTC times, without document text, names, passwords, bearer tokens or prior values. The authenticated API exposes the latest 500 events for an active matter. These events are mutable local records, not a certified legal audit trail. The newest 100 edit-history events per matter are retained; terminal jobs have a 90-day policy. Routine HTTP access logging is disabled and packaged Tauri suppresses raw sidecar stderr. Do not add credentials, request bodies, OCR text or file contents to logs.

## Verification boundary

Synthetic pytest cases cover credential failure/recovery/rotation, tampering, interrupted writes and migration, encrypted SQLite, protected import/edit/build/export, and same- and cross-vault backup/restore. A protected Chromium setup/unlock journey and frozen Apple Silicon sidecar PDF/OCR/export smoke test passed on macOS. The built macOS app and DMG compiled, and the native app reached the new-vault setup screen with a disposable data directory. Native WebView credential entry and Save/Open dialogs, Windows permissions and crash recovery still require device checks under NAT-01/NAT-03. PDF-09 remains gated separately; a vault password does not implement password-protected PDF import or export.
